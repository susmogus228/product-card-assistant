# Проверка прототипа

> Дополнение: последующая независимая сверка обнаружила пропущенные условия точности
> и эксплуатации в исходных данных демонстрационных товаров. См. [повторную сверку](review-2026-11-03.md).
> Утверждения ниже о соответствии демонстрационных карточек нужно читать с учётом этого исправления.

Дата проверки: 3 ноября 2026 года. Среда: Windows, Python 3.12.14.

## Локальная проверка

- 83 автоматических теста проходят в рабочем и отдельном чистом venv.
- `ruff check .` проходит; `ruff format --check src tests` проходит.
- Установка из `requirements.lock`, затем `pip install -e . --no-deps` выполнена
  в новом окружении. Консольная команда `product-card --help` работает.
- Проект дополнительно распакован из исходного ZIP в отдельный каталог: там проходят
  те же 83 теста, lint и format. Пустой `work/.gitkeep` обеспечивает запуск тестов
  после свежей распаковки. `.gitattributes` сохраняет LF и воспроизводимость хешей
  исходных JSON после Git checkout на Windows.
- Автоматические тесты используют подставной HTTP-транспорт и не обращаются к API.
- Два положительных примера ниже получены отдельными реальными вызовами CLI через
  Groq API, модель `openai/gpt-oss-120b`. Финальные тексты не заменялись вручную.

## Сверка с источниками

- Для 905-T1 сохранены основной диапазон и условие кратковременного измерения до
  +500 °C только в течение 1-2 минут, две полосы погрешности и температура настройки
  +25 °C, отклик t99 в воде. Финальный текст не предлагает погружать весь прибор.
- Для 608-H1 сохранены диапазоны температуры и влажности, условие точности при
  +25 °C. Текст описывает точку росы как вычисляемую величину. Сигнализацию модели H2
  в карточку H1 не переносили.
- Commercial-блоки состоят из точных предложений входного описания. Новые области
  применения в них не добавлены. Проверка не подтверждает пригодность для любой
  конкретной среды или регулируемого применения вне исходных сведений.
- Официальные страницы и PDF производителя перечислены в `examples/sources.json`.
  Данные PDF также сверены после локального чтения: технические таблицы на второй
  странице каждого datasheet. Исходные паспорта не входят в распространяемый пакет.

## Ошибочные входы и API

Три CLI-примера с повреждённым JSON, неверными типами и повторяющимся ключом дали
код 2. Примеры `incomplete.json` и `prompt-injection.json` дали `needs_data`, код 4,
без генерации. Контролируемый тест противоречия подтверждает подавление SEO-текста
и пометку спорного значения «требует уточнения».
Реальный запуск `conflicting.json` также вернул код 4, `needs_data` и
`specs.масса: противоречие с description` после одной генерации.

В реальной работе также получен ответ ограничения квоты Groq; CLI вернул понятное
сообщение и код 3, файл карточки не создал. Таймаут, 401, 403, 400, 429, 500,
повреждённый HTTP 200, пустой `message`, неверный/обрезанный JSON покрыты тестами SDK
через подставной HTTP-транспорт. Реальные ошибки авторизации и сервера намеренно не
вызывали: подставные проверки не выдаём за живые сетевые результаты.

При настройке проверок обнаружены и исправлены: типографский минус, знаки после
слова, варианты `mm/мм`, различие масштабов `МПа/мПа`, новые числа перед буквенной
единицей, пробельные варианты имён характеристик и пустое сообщение API. Для каждого
существенного исправления сначала воспроизведён сбой тестом, затем получен проход.

## Независимая проверка

Профиль `requirements-auditor` не запустился из-за недоступной для аккаунта модели;
вердикт от него не получен. Доступный отдельный агент провёл проверку только чтением.
Кодовый аудит после исправлений: PASS с описанными в README ограничениями смысловой
проверки. Финальная независимая сверка двух JSON/Markdown результатов: PASS.
Проверяющий подтвердил длины, совпадение всех 38 характеристик и хешей исходников,
условия точности, кратковременный диапазон и вычисляемую точку росы.
Неблокирующая редакторская мелочь в исходном ответе модели: «с встроенным зондом»
можно заменить на «со встроенным зондом». Финальный пример сохранён без ручной подмены.

## Границы результата

- Товары являются согласованными демонстрационными примерами. После получения данных
  работодателя нужно повторить генерацию и сверку на его товарах.
- Git-репозиторий создан локально. Внешний Git push, публикация репозитория и ссылка
  для сдачи ещё не выполнены.
- Генератор создаёт черновик; лексические проверки и цитаты не доказывают все смысловые
  утверждения. Пропуск конфликта моделью и неизвестные единицы остаются ограничениями.
- API бесплатен в пределах квоты аккаунта. При исчерпании лимита нужен последующий
  запуск после его восстановления. Программа не меняет тариф.
- Linux/macOS и веб-интерфейс не проверялись; веб-интерфейс не входит в этот прототип.
