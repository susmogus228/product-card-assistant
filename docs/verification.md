## Дополнительные демонстрационные карточки

Для расширения подборки через текущий локальный CLI Ollama сформированы карточки
Fluke 62 MAX и testo 510. Входные данные самостоятельно подготовлены по материалам
производителей, а не предоставлены работодателем. Fluke: заголовок 61 символ,
описание 1101, пять запросов и 13 исходных характеристик; добавлен извлечённый из
описания пункт «Применение». Testo 510: заголовок 67 символов, описание 892, пять
запросов и 11 характеристик. Все исходные значения совпали с подготовленными JSON;
ключевые диапазоны и условия сверены с доступными материалами производителей.
В обоих результатах сохранено предупреждение об исключённых неподтверждённых кандидатах: карточки
остаются черновиками и требуют ручной проверки. Результаты и входы находятся в
`outputs/` и `examples/products/`; источники и хеши — в `examples/sources.json`.

## Итоговая локальная проверка изменений

В рабочем и отдельном окружении выполнены 137 автоматических тестов; `pip check`,
`ruff check .` и `ruff format --check src tests` проходят. Два актуальных примера
Ollama для подготовленных демонстрационных входов: [905-T1](../outputs/testo-905-ollama.md)
— описание 828 символов, 17 исходных характеристик; [608-H1](../outputs/testo-608-ollama.md)

Оба содержат предупреждение: некоторые предложенные характеристики не прошли
проверку и исключены, описание требуется проверить вручную. Это ограниченное
число демонстраций, а не оценка на всех товарах.

## Поштучная проверка дополнительных характеристик

Некорректные элементы извлечения исключаются отдельно с предупреждением в JSON и
Markdown; другие подтверждённые элементы сохраняются. Дубликаты с одинаковым
значением не повторяются. Два разных подтверждённых значения одного поля не
выбираются автоматически; поле или данные передаются на уточнение. Цитаты также
проверяются в контексте предложения, чтобы не принимать фрагмент, скрывающий
«не подтверждено». Это ограниченная проверка, а не полноценное понимание смысла.

Контрольные проверки с подставным API охватывают смешанные и полностью ошибочные
ответы, повреждённый элемент, пропуски, дубликаты, противоречия, цитаты и их
контекст. На реальной Ollama testo 510 и testo 905-T1 сформировали черновики с
предупреждением об исключённых неподтверждённых элементах; все исходные значения
сверены с подготовленным входом. На искусственно изменённом входе Fluke 62 MAX
три характеристики, перенесённые в описание, были извлечены с дословными цитатами.
Синтетическое противоречие 80/90 г вернуло `needs_data` без SEO-описания.
Один запуск каждого случая не подтверждает стабильность на произвольных данных.
Во время проверки результаты первоначально сохранялись локально; настройки сервера
не изменялись. Два свежих результата Ollama дополнительно доступны в `outputs/`.

## Ещё два прибора и противоречивый ввод

На локальном CLI через Ollama проверены ранее подготовленные данные двух других
приборов: Fluke 62 MAX и testo 510. Fluke: карточка создана, 13 характеристик
совпали с входом, описание 1111 символов; существенные диапазоны, условия точности
и питания вручную сверены с подготовленным JSON. Testo 510: обе попытки отклонены
с кодом `unverified_additional_spec`, карточка не сохранена. В отдельном
диагностическом запросе модель представила как цитату слова, отсутствовавшие в
описании. Поправка к инструкции не помогла в одной дополнительной попытке и была
отменена. Это означает, что локальные проверки предотвращают выдачу неподтверждённой
характеристики, но стабильная генерация для такого входа пока не обеспечена.

Дополнительно искусственный вход с противоречием массы 90 г и 80 г вернул
`needs_data` и «требует уточнения» без SEO-описания. Приведённые проверки не
доказывают выявление любого противоречия или отсутствие всех смысловых ошибок.
Работодатель ещё не предоставил свои исходные товары; все приведённые товары и
вход с противоречием — демонстрационные. Изменения пока не опубликованы.

Выполнены два последовательных реальных запуска текущего локального CLI через
Ollama. Обычный `testo 905-T1`: 17 характеристик совпали с подготовленным входом,

Оба результата — черновики, проверенные по подготовленным демонстрационным данным;
файлы находятся в локальном `work/fact_v2_api/` и не входят в Git.

Первый запрос testo 905-T1 был отклонён из-за ложного определения единицы измерения
в конце названия модели. Исправлено правило разбора; тесты подтверждают также
сохранение знака отрицательных температур. Во время ручной проверки отдельной
генерации обнаружена неоднозначная фраза про погружение зонда в вентиляционные
каналы; для известного случая используется точное предложение из источника.

Эти проверки не гарантируют достоверность произвольных товаров. Работодатель пока
не прислал два требуемых входа; сданные тестовые товары должны быть явно названы
демонстрационными. Адрес и доступ к удалённому серверу в публичный репозиторий не
включены; для запуска другому человеку нужна доступная ему Ollama либо Groq.
На момент этой проверки локальные изменения ещё не были опубликованы.

## Проверка Ollama после уточнения ограничений

Ограничение длины в схеме Ollama возвращено к 1200 символам. Для известных ситуаций
программа подставляет точные условия из входных характеристик или исходное предложение
из описания; неизвестные значения не заполняются. Отдельные тесты проверяют, что
другие диапазоны и отсутствующие условия не дополняются догадкой.

Реальные последовательные запуски текущего локального CLI: testo 608-H1 — 1049
символов описания, 21 характеристика; testo 510 — 891 символ, 11 характеристик,
включая три извлечённые с цитатой. Все значения сверены с подготовленными входами.
В обоих случаях перед выдачей требуется ручная проверка; один успешный запуск на
товар не подтверждает надёжность на произвольных данных. Вход testo 510 был изменён
для проверки извлечения, поэтому не является прямой копией документа производителя.
На момент этой проверки изменения и результаты были локальными.

## Локальное подключение Ollama

Добавлен альтернативный провайдер Ollama: два вызова на попытку, проверка цитат,
условий и контроль ошибок. Адрес сервера хранится в непубликуемом локальном `.env`;
пример конфигурации оставляет адрес пустым. Настройки Ollama и других
проектов на сервере не менялись; влияние запросов на общий ресурс не измерялось.

Реальный CLI создал черновики Fluke 62 MAX и testo 510 на подготовленных входах,
где часть характеристик была перенесена в описание; по три характеристики каждого
товара извлечены с цитатами. Для testo 510 один ранний запуск не прошёл проверки,
следующий успешно завершился; ранее успешный запуск Fluke был до последующих
небольших изменений промпта. Отдельный полный вход testo 608-H1 на текущей версии
после двух попыток был отклонён по `accuracy_condition`; результат не сохранён.
В дополнительном диагностическом ответе модель указала погрешности, но пропустила
условие «дополнительно ±1 единица младшего разряда», поэтому это срабатывание
проверки было обоснованным. Последующий запуск testo 510 отклонён по
`accessory_condition`; содержимое отклонённого ответа не сохранено, поэтому нельзя
подтвердить причину срабатывания или исключить ложное срабатывание.
Таким образом, гарантировать стабильную генерацию по всем товарам пока нельзя.
Коды ошибок не означают, что прочие смысловые ошибки исключены.

## Ошибочные входы и API

Три CLI-примера с повреждённым JSON, неверными типами и повторяющимся ключом дали
код 2. Примеры `incomplete.json` и `prompt-injection.json` дали `needs_data`, код 4,
без генерации. Контролируемый тест противоречия подтверждает подавление SEO-текста
и пометку спорного значения «требует уточнения».
Реальный запуск `conflicting.json` также вернул код 4, `needs_data` и
`specs.масса: противоречие с description` после одной генерации.

В реальной работе также получен ответ ограничения квоты Groq; CLI вернул понятное
сообщение и код 3, файл карточки не создал. Таймаут, 401, 403, 400, 429, 500,
повреждённый HTTP 200, пустой `message`, неверный/обрезанный JSON покрыты тестами SDK
через подставной HTTP-транспорт. Реальные ошибки авторизации и сервера намеренно не
вызывали: подставные проверки не выдаём за живые сетевые результаты.

При настройке проверок обнаружены и исправлены: типографский минус, знаки после
слова, варианты `mm/мм`, различие масштабов `МПа/мПа`, новые числа перед буквенной
единицей, пробельные варианты имён характеристик и пустое сообщение API. Для каждого
существенного исправления сначала воспроизведён сбой тестом, затем получен проход.

## Границы результата

- Товары являются согласованными демонстрационными примерами. После получения данных
  работодателя нужно повторить генерацию и сверку на его товарах.
- На момент первоначальной проверки репозиторий был только локальным. Позднее он был
  опубликован; текущий адрес указан в README.
- Генератор создаёт черновик; лексические проверки и цитаты не доказывают все смысловые
  утверждения. Пропуск конфликта моделью и неизвестные единицы остаются ограничениями.
- API бесплатен в пределах квоты аккаунта. При исчерпании лимита нужен последующий
  запуск после его восстановления. Программа не меняет тариф.
- Linux/macOS и веб-интерфейс не проверялись; веб-интерфейс не входит в этот прототип.
